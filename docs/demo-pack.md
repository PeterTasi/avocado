## 一、Demo 講稿（5 分鐘版）

### 開場 hook（0:00–0:30）

> 「每個學生都遇過這件事：考前打開筆記，卻不知道**該從哪裡讀起**、**哪裡最弱**、**讀了記不記得住**。AdaptLearn 把這三個問題變成一條自動化的流水線——上傳教材，系統自己回答這三題。」

（講的同時打開首頁，讓像素酪梨 landing 進場動畫跑完——不要跳過，這是記憶點。）

### 第一幕：手寫筆記 → 知識圖譜（0:30–1:45）

操作：上傳準備好的**手寫筆記照片/掃描 PDF**（這是差異化亮點，別用純文字 PDF 開場）。

> 「注意我上傳的不是打好字的講義，是**手寫筆記**。系統走一條 OCR 備援鏈——本地 Ollama 視覺模型優先、雲端 Gemini 兜底——轉寫後由 LLM 抽取概念與先修關係，建成知識圖譜。」

等待 ingest 時（進度條會顯示真實階段），順勢講架構：

> 「處理是非同步的：後端開工作執行緒、前端輪詢進度，所以再大的檔案也不會讓網頁卡死。」

圖譜出來後，指著先修邊講一句話重點：

> 「這不是關鍵字雲——邊是**先修關係**。等一下你們會看到，系統就是沿著這些邊決定『你該先補哪裡』。」

### 第二幕：自適應診斷（1:45–3:00)

操作：產生 6–9 題測驗，答 2–3 題（故意答錯一題）。

> 「出題不是隨機的：系統對每個概念維護掌握度，**優先攻擊最弱和沒測過的概念**。作答是開放式的，由 LLM 批改、給繁中回饋——不是選擇題比對答案。」

答錯那題出現回饋時停一秒：

> 「注意它不只給分數，還指出推理哪裡斷掉。這個分數會立刻回流到掌握度和複習排程。」

### 第三幕：遺忘曲線與今晚計畫（3:00–4:15）

操作：切到複習頁。

> 「這裡是整個系統的核心演算法：**FSRS-5 間隔重複**——和 Anki 最新排程器同一家族。每個概念是一張卡片，我們把作答歷史重放進模型，重建它的記憶穩定度，算出『現在還記得的機率』。」

指著今晚優先清單：

> 「所以『今晚先讀什麼』不是老師拍腦袋，是遺忘曲線算出來的：**快忘掉的、又是弱點的，排最前面**。旁邊還有預估的通過率提升。」

（若有多天的作答資料，秀掌握度趨勢 improving/declining。）

### 收尾（4:15–5:00）

操作：回到圖譜頁，若有兩門課，秀跨課程虛線橋接；或秀班級熱力圖。

> 「最後兩個彩蛋：系統會用向量語義搜尋，自動發現**跨課程的同構概念**——線代的特徵向量和機器學習的 PCA 會被接起來。老師端則有班級熱力圖，一眼看出全班共同卡關的概念。」
>
> 「總結：AdaptLearn 把『讀哪裡、弱哪裡、記多久』三個問題，變成上傳一份檔案就能回答的事。謝謝。」

### 備援劇本（必讀）

- **API 掛掉/額度用盡**：系統會自動降級（模板題目、heuristic 批改），不會白屏。話術：「這正好展示我們的優雅降級設計——沒有金鑰它仍是可用的產品。」
- **OCR 太久**：先用**已 ingest 過的課程**講圖譜（OCR 有以檔案 hash 為 key 的快取，重傳同一份檔案秒回），把上傳流程留到最後有剩時間再演。
- **現場網路差**：本地 Ollama OCR + 預先 ingest 的資料能撐完整場，只有出題/批改需要網路。

## 二、評審 Q&A 預想（附建議回答）

**Q1：這跟 ChatGPT 丟筆記叫它出題有什麼差別？**
> 差在**狀態**。ChatGPT 每次都是無記憶的一次性生成；我們對每個概念持續維護掌握度和 FSRS 記憶模型，出題、批改、排程互相回饋，是一個閉環系統。LLM 只是其中的感知元件，不是產品本身。

**Q2：為什麼選 FSRS-5？和 SM-2（傳統 Anki）差在哪？**
> SM-2 是 1980 年代的啟發式規則；FSRS-5 是用上億筆真實複習紀錄訓練出來的機器學習模型，能顯式估計「此刻的回憶機率」。我們需要這個機率當排序依據——「今晚先讀什麼」本質上是按遺忘風險排序。

**Q3：通過率預估的公式怎麼來的？有驗證嗎？**
> 誠實回答：目前是經驗式的線性組合（基準 0.32 + 平均分、正確率、經驗加權），**還沒用真實世代資料驗證**，程式註解裡就標明是 placeholder。設計上預留了之後用 logistic regression 校準的位置。（誠實比吹牛加分——這題就是在測誠實。）

**Q4：手寫辨識準確率如何？辨識錯了怎麼辦？**
> OCR 是四層備援鏈（Ollama → Chandra → Gemini 整份 PDF → Gemini 逐頁），取第一個非空結果。完全失敗時系統會**明確警告**使用者「目前顯示的是模板概念、不是你的教材」，絕不默默給假資料——這是我們修過的真實 bug，教訓寫進了設計原則。

**Q5：多個學生同時用會怎樣？**
> 目前是單租戶架構（比賽 scope 的取捨）：courses 表已有 user_id 欄位、concept ID 已按課程隔離，資料層準備好了；缺的是認證層和 session 隔離，這是明確的 roadmap 而不是設計缺陷。

**Q6：成本？沒有 API 金鑰能用嗎？**
> 能。OCR 可全走本地 Ollama（零 API 成本），沒有任何金鑰時降級成模板題目 + 關鍵詞批改。有金鑰時預設用 gemini-flash 系列，單次 ingest 成本約在幾分錢等級，且有模型自動降級鏈（額度用盡自動換較舊的 flash 模型）。

**Q7：學生的筆記資料隱私？**
> 教材文字存在自家 PostgreSQL；送 Gemini 的內容僅用於當次轉寫/出題，不做訓練（Gemini API 政策）。本地 Ollama 路徑則完全不出機器。

**Q8：知識圖譜的邊是 LLM 生成的，怎麼防幻覺？**
> 三道防線：(1) prompt 限制先修關係只能指向同批抽取的概念；(2) 後處理過濾週次/作業/公告等行政雜訊（有專門的 noise terms 清單）；(3) 概念 ID 用 uuid5(課程:章節:名稱) 決定論生成，同名概念不會分裂成多個節點。

## 三、海報文案

### 主標語（擇一）

1. **「上傳筆記，剩下的交給遺忘曲線。」**
2. 「知道你哪裡不會，比你自己更早。」
3. 「從手寫筆記到考前計畫，一條龍的個人化學習引擎。」

### 一句話定位

> AdaptLearn：把課程教材自動轉成知識圖譜、自適應測驗與 FSRS-5 間隔複習計畫的 AI 學習平台。

### 三欄亮點（海報中段）

| 📷 看得懂手寫 | 🎯 打得中弱點 | ⏰ 算得出遺忘 |
|---|---|---|
| 四層 OCR 備援鏈（本地 Ollama 優先、Gemini 兜底），手寫筆記直接變教材 | LLM 依「掌握度最低 + 未測過」的概念自適應出題，開放式作答、AI 批改給繁中回饋 | FSRS-5 重放作答歷史、重建記憶穩定度，按回憶機率排出「今晚先讀什麼」 |

### 系統架構一句話（海報底部）

> React SPA ─ FastAPI ─ PostgreSQL ＋ ChromaDB 向量庫；Gemini 負責感知（OCR/出題/批改），FSRS-5 負責記憶模型，知識圖譜負責結構——LLM 是元件，不是產品。

### 差異化聲明（評審巡場時的 30 秒版）

> 「市面上的 AI 學習工具大多是『聊天視窗包一層皮』。我們的差異是**持久的學習者模型**：每個概念有掌握度、有 FSRS 記憶狀態、有圖譜位置，AI 的每次輸出都在更新這個模型，而不是一次性的生成。」

## 四、Demo 前檢查清單

- [ ] `.env` 有可用的 `GEMINI_API_KEY`，且額度充足（前一晚先打一次確認）
- [ ] 本地 Ollama 起著、`OLLAMA_OCR_MODEL` 設好（現場斷網保險）
- [ ] 至少一門課**前一晚先 ingest 好**（OCR 快取生效，現場重演秒回）
- [ ] 準備兩門有概念重疊的課程（跨課程橋接 demo 用）——⚠️ 先確認 `docs/fable5.1-review.md` 第 1 項修了沒，沒修的話跨課程連結可能是空的，**這段就從講稿拿掉**
- [ ] 答錯用的題目先想好錯法（錯得有教學價值，讓 AI 回饋有東西講）
- [ ] `webapp/frontend && npm run build` 是最新的（改過前端就要重 build）
- [ ] 手機熱點備援
